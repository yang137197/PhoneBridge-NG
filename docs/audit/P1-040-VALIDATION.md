# P1-040 签名备份物理独立性检查验收

日期：2026-09-23。结果：同盘失败关闭通过；外置介质正向路径未运行。

## 已确认

- 初始化脚本现在要求主密钥位于本地固定磁盘。
- 固定卷备份按 `Get-Partition` 返回的物理 `DiskNumber` 与主卷比较；同一物理磁盘上的其他分区或盘符不能冒充独立备份。
- 备份允许的存储类别为不同物理磁盘的固定卷、可移动卷或网络卷。网络卷只代表路径位于远端，不能证明远端后端磁盘、加密或管理策略。
- 当前主机只有一个 NVMe 物理磁盘，C: 和 D: 都是 Disk 0。C:→D: 与 C:→C: 两个真实拒绝用例均退出 1。
- 网络路径作为主目录和不存在的备份卷也分别退出 1。
- 四项失败全部发生在创建目录、读取密码和生成密钥之前；测试路径存在数量为 0，正式身份没有创建。
- 当前说明已随默认 `LocalTest` 交付重建：安装器大小 81,083,764 字节、SHA-256 `B357083FD1B53491BE9F7C2E1378450B31BAC7FBA47EF63363D39F9158F280A1`；APK SHA-256 保持 `B6831F1C580C1337E9A0FDC4DB8BB21FD328AE90D9E0C2625DB61D170C6D33BC`，Windows 发布 DLL仍与 P1-030 相同。

机器可读证据：`.audit/runs/P1-040/physical-independence-verification.json`。

## 未验证与边界

当前没有第二块物理磁盘、可移动卷或映射网络卷，因此没有执行外置介质正向生成。P1-036 已在物理检查加入前验证密钥生成、双份散列/证书一致性和 ACL；P1-040 新增的“外置存储通过后继续同一流程”要在真实设备接入时验证。

脚本不会检查或启用 BitLocker，也不能判断 NAS/网络共享后端是否与主机物理独立。操作者仍须选择真正独立且受保护的介质并保存密码。
