# P0-009 Android 证书与 rclone 身份绑定

- 状态：已完成限定 TLS 任务；真实手机 LAN 与两个模拟器验证通过，完整文件链路另由 P0-010 验收
- 目标：修复 P0-008 真机 TLS 阻断，在每条真实 rclone 连接中校验稳定设备身份，并支持地址改变后继续使用同一配对身份；解决 D-04 后返回完整真机链路。
- 范围：依据 rclone v1.75.1 与 Android Keystore 官方能力，先更新架构与身份/证书语义，再实现最小可验证方案；包含 SAN、密钥保存、TLS 失败停止共享及真实错误身份拒绝测试。
- 不做什么：不跳过证书校验、不加入自制密码协议、不修改系统信任库/hosts，不把仅适配当前固定 IP 当作最终身份方案；不实现 WPF、正式配对 UI 或发布 APK。
- 涉及文件：独立修复副本、Android TLS/服务最小改动与测试、rclone 真实连接验证、ARCHITECTURE/DECISIONS/PROTOCOL 和审计证据。

## 实现

先读 [P0-008 证据](../../audit/P0-008-VALIDATION.md)：上游证书没有 SAN，添加信任仍被 Go 地址校验拒绝。单次证书探针后传 no-check-certificate 不合格。rclone 的 ca-cert 实际建立独立 RootCAs 池，可作为候选能力，不能凭文档就认定已完成身份绑定。

采用 Android Keystore 中的稳定设备 CA 与 TLS 密钥，由 CA 签发含当前接口 IP SAN 的短期服务器证书。rclone 仅信任已确认的设备 CA 并实际校验地址；CA 指纹变化必须拒绝并重新配对，正常叶证书轮换保持身份。缺失/损坏/过期材料或旧 PKCS12 会停止共享，不能静默换身份或降级 HTTP。限定证据支持 ADR-014，正式配对和 Windows 信任材料保护仍待实现。

## 测试

真实 rclone 正确身份成功；不可信/替换证书、错误地址、损坏材料及 TLS 初始化失败均在认证/写入前拒绝；运行中的连接不能靠前置探测绕过实际验证。验证至少两个可达地址和重启后稳定身份。核对 minSdk 26 的 API 分支、构建/Lint、应用与测试 APK 散列及最终补丁；不得只写模拟 TLS mock 测试。

## 验收结果

详见 [P0-009 验证记录](../../audit/P0-009-VALIDATION.md)。最终构建退出 0，25 单元、Lint 0 errors/117 warnings；API 26/36 与备用机各 8 项原生通过。三者的实际服务/rclone 正向、错误身份/地址拒绝、进程重启、损坏材料停止及原证书恢复通过。真机同一身份同时通过 USB 转发的 loopback 与真实 LAN 两个端点，完整入口退出 0，共 18 个通过记录（含 5 次前台测试启动）。地址集合轮换由原生真实 TLS 测试注入；实际 DHCP 换 IP、手机整机重启未测。

手机已显式迁移此前的实验 PKCS12，现使用新 Keystore 身份；不涉及正式配对重置。Music 选择、原有两个缩略图元数据文件和关闭自启保留，共享停止、转发和测试控制文件移除，两个 AVD 已退出。USB 重连后另外定位到 ROM 拒绝测试进程后台打开 Activity；用标准 ADB 启动公开前台界面后测试通过，没有改权限/系统保护。用户已有的备用机测试与更新授权继续有效。
