# P0-010 受验证 TLS 保护的真机文件链路

- 状态：限定链路验收完成；首轮工具失败由独立界面确认和宿主收尾回归补证
- 目标：补齐 P0-008 因 TLS 阻断而未执行的真机挂载、读写、双向 100 MB 复制和退出，复验 CHAIN-01–06。
- 范围：已授权、已清空的 Redmi K40；精确核对设备、P0-009 APK 散列、Music 根和当前网络。USB 只用于安装、读取公有身份和独立文件校验；传输走真实 Wi-Fi/LAN。rclone 每条连接均启用设备专属 CA 与端点校验。
- 不做什么：不改变系统信任/权限，不使用 no-check-certificate，不覆盖或删除 Music 既有元数据，不测试主手机、不发布、不开始 WPF。1/5/10/20 GB、断网/休眠/实际换 IP、三星与完整配对另行验收。
- 涉及文件：真机专用链路实验入口、任务和审计报告、测试矩阵。若发现核心缺陷，先取证再拆分最小修复。

## 实现

沿用 [P0-009](../../audit/P0-009-VALIDATION.md) 的最终累计补丁、APK 与稳定设备身份，不重新生成已有身份。当前手机共享已停止、自启关闭；用户对实验 APK、Music 和真机测试已有授权，无需重复请求。ROM 拒绝测试进程后台拉起 Activity，前台测试可使用标准 ADB 的公开启动入口；不得修改厂商私有权限来使测试通过。

新建带任务标记的专用测试子目录，仅写入可确定归属的合成文件，使用全新目标名和独立 Windows VFS 缓存。保留 Music/.thumbnails 两个既有文件。测试失败时先停止传输并核对待上传状态，不强删缓存或非测试数据。

## 测试

按 [TESTING](../../TESTING.md) 的 CHAIN-01–06 逐项记录：启动监听后 mDNS 实际发现；真实局域网 HTTPS 认证；空闲盘符挂载；Explorer 实际可见/枚举证据；含文本与不同区段的 100,000,000 字节样本双向复制；手机端独立大小/SHA-256 与 PC 一致；卸载后盘符、服务、子进程和缓存状态回读。文件复制本轮必须实际经过 rclone/WinFsp。通过 COM 自动观察与人工视觉观察分开记录，不冒充用户操作。

执行前核实手机当前地址与身份、USB 在线、WinFsp 状态和空闲盘符；不沿用历史 IP 作为默认事实。手机 Wi-Fi、PC 有线同 LAN 的结果不能写成两端同时 Wi-Fi。

## 验收结果

六项链路均有实际证据：3.469 秒发现、可信 HTTPS 认证、P: 挂载、用户确认四个项目可见、双向 100,000,000 字节和文本独立散列一致、创建/重命名与退出。首轮界面观察超时，第二次宿主退出遇到 ROM 后台 Activity 拒绝；两次完整入口均退出 1，不改写历史。收尾包装修复后，后台状态退出的独立回归退出 0，控制文件/进程/服务/转发均已清理。

完整证据与限制见 [P0-010](../../audit/P0-010-VALIDATION.md)，Phase 0 门槛核对见 [阶段收口](../../audit/PHASE-0-ACCEPTANCE.md)。仍非正式产品；样本和缓存保留。下一任务 [P1-001](../completed/P1-001-windows-discovery.md) 建立 Windows 工程与设备发现模块。
