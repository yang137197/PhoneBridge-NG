# P1-007 Android 首次配对与授权服务

状态：已完成限定任务。

## 目标

将已验证的配对核心与两端存储契约接到 Android 宿主，完成可实际运行的“短码配对 → 严格 TLS 提交 → 手机明确批准 → session 验证 → 撤销”最小闭环，推进到应用行为而非继续增加独立基础库。

## 范围

建立正式 Android 工程，按固定上游与累计 P0-009 补丁导入必要的身份/前台共享基础，保留作者、许可和来源。先核实 Kotlin 2.4 协议核心与 AGP/存储编译组合，更新架构后再集成。实现前台限时配对窗口、单工作者/5 次预算、真实 TCP 帧收发、绑定当前身份的 grant、严格有界 HTTPS 授权接口及中英文批准/拒绝/撤销界面；Active 必须在 Keystore 持久成功后回执。复用已验证文件路径/TLS 基础，正式路径拒绝实验明文账号回退。

实际 session/self 撤销与只读文件请求验证经过新认证；安全模式仍是正式默认，删除/覆盖确认未实现前继续拒绝相应写操作，不宣称完整安全模式。网络活动流取消、手机端停止共享和存储失败行为必须可验证。优先专用 API 26/36 模拟器与 C# 协议/存储测试客户端，测试宿主不是新的 Windows GUI。

## 不做什么

不做 Windows WPF/托盘/自动重连、安装器/发布、D-05 删除覆盖确认、D-06 写缓存或性能优化。不改手机账号/安全策略，不隐式迁移旧实验密码或丢失的身份；正式新应用使用独立应用 ID，真机安装/数据范围若需要再依据现有授权和现场状态核对。

## 涉及文件

android 正式 App/构建与中英文资源、两个模块必要兼容适配、测试用 C# 网络宿主、协议/授权集成测试、ARCHITECTURE/DECISIONS/PAIRING/SECURITY/TESTING 和验收记录。保留旧模块测试与 P0 产物，不大规模重构已验证文件服务。

## 实现

先从本任务、P1-004/005/006 验收及 PAIRING 契约恢复边界。冻结并记录网络监听/关闭、期限/预算、批准取消竞争、重复提交、授权路由与存储失败状态；再实现和复核。不得自行放宽帧/密码参数、信任发现数据、跳过 TLS 或用调试接口代替手机明确批准。

## 测试

实际两端网络正向和错误码/重放/超时/预算；无 PAKE 确认时零长期 token 发送；错误 CA/地址拒绝、批准/取消/回执丢失恢复、同 token 重试与变更拒绝、多个电脑隔离、撤销重启/活动流阻断、损坏/写失败停止共享。检查日志/进程参数/普通配置不含合成秘密。对正式 App 做构建/Lint与 API 26/36 原生集成，按实际执行范围更新产品矩阵，不沿用纯模块通过结果。

## 验收结果

已完成：正式 Android NG 应用、限时 TCP PAKE、严格 HTTPS 提交/手机批准/session、每请求认证与撤销流取消、中英文界面和前台服务。严格构建/Lint/15 项协议测试通过；API 26/36 各 42 原生及 C# 联动通过，包含进程重启和真实服务存储故障停共享。首轮 API 36 撤销失败及修正保留。详见 [P1-007 验收](../../audit/P1-007-VALIDATION.md)。未覆盖真机/OEM、mDNS 实测、网络切换、Windows 正式界面/挂载、安全写入和完整生命周期；整个 MVP 未完成。唯一下一任务为 P1-008 Windows 首次配对与只读连接界面。
