状态：当前 MVP-01–15 已按最终需求全部通过，Windows 自启动只进入托盘并等待手动连接；大文件、恢复、Seek、目录性能和 Samsung/Redmi 链路也已有分任务证据。P0-003 至 P1-030 的段落保留各任务当时范围，历史“未验收”不能覆盖后续结果。当前产品缺口以 [P1-039 就绪度复核](audit/P1-039-VALIDATION.md) 为准；P1-034 是签名工具链实现前的历史审计。原版事实见 [P0-003](audit/P0-003-VALIDATION.md)，离线审计见 [P0-001](audit/VALIDATION.md)。

## 1. 结果与证据格式

每项结果只用“通过、失败、阻塞、未运行、不适用”，填写[验收模板](tasks/VALIDATION_TEMPLATE.md)。记录源码提交/patch、应用/依赖版本、系统版本、设备类型、执行人/时间、精确测试数据、期望、实际、退出码/错误和证据位置。

模拟器与 Galaxy S23 Ultra 分列；mock、协议工具、真实 Explorer 分列。测试成功至少需要回读实际文件/盘符结果；进程存活或 UI 提示不能替代。

原始日志和临时文件存本地 `.audit/runs/<任务编号>/`；只有经过脱敏的摘要和合成数据校验值进入 docs。禁止真实文件、密码、完整认证 Header、私钥或签名密钥进入证据附件。

### 2.2 数据隔离要求

上游的共享根选择仅有整个外部存储/DCIM/Download/Music，并有越界及错误回退风险。**在主手机 DCIM 下新建一个测试子文件夹不构成安全隔离。** 所选共享根及服务权限可能访问到的数据必须均可丢弃；Windows 回读/缓存目录也须单独创建且不含用户文件。

推荐先使用无账号、无个人数据的 Android 模拟器或专用测试机；模拟器若不支持当前网络发现拓扑则记录限制，不能只用手动 IP 成功替代自动发现测试。原始 Python HTTP 模拟服务只能辅助测试 Windows，不能完成 Android HTTPS 原始链路验收。

若必须修改上游才能安全限定范围或成功构建/挂载，先记录阻塞点，下一次单独执行最小修复任务；保留原始证据，修复版单独标识。文档阶段不预先承诺所有环境都能完成原版验收。

### 2.3 有序执行矩阵

每一步成功且没有停止条件后再继续；这里不是让用户现在一次执行所有步骤。

| ID | 检查 | 成功证据 | 失败/停止条件 |
| --- | --- | --- | --- |
| CHAIN-01 | 构建/启动 Android 共享 | 可追溯 APK、已授予权限、前台通知、实际端点/共享根 | 构建失败、权限缺失、HTTP 降级、共享根变宽 |
| CHAIN-02 | mDNS 发现与 HTTPS | 实际解析的端点、协议、证书信息；记录发现时间 | 协议/端点异常；发现失败单独记录，手动 IP 仅辅助定位 |
| CHAIN-03 | 首次挂载和目录浏览 | Explorer 真实盘符、目录读取、唯一受管 rclone 进程 | 盘符未就绪、进程重复、Explorer 卡死、超时无法退出 |
| CHAIN-04 | 手机 → PC 读取/复制 | 合成样本至少含文本及 100 MB 文件；两端大小和 SHA-256 一致 | 内容不符、读错路径、只拿到部分内容 |
| CHAIN-05 | PC → 手机写入/复制 | 使用新文件名上传合成数据；确认上传完成后手机端独立计算大小/哈希，再回读 | 写入错误、结果仅在缓存、覆盖了非测试文件 |

最小链路样本不能代替下方大文件专项。未经验证，不在原版做根 DELETE、异常路径或已有文件破坏性覆盖；这些问题采用单独协议/修复任务在牺牲数据中验证。

### 2.4 P0-003 通过标准

CHAIN-01–06 均有实际结果，Android → HTTPS/WebDAV → rclone → WinFsp → Explorer 完整链路的挂载、读取、写入、双向复制和退出均成立，大小/哈希一致。任一缺失、失败或阻塞都不能记“完整通过”。手动连接成功、模拟器成功的范围限制必须明确。

原始上游开发态 TLS 的测试若跳过证书检查，仅能说明隔离实验的文件链路行为，不能说明身份安全。凭据或文件边界无法满足要求时停止相关路径，不为追求“链路通过”放宽项目约束。
