# P1-029 PC 睡眠/唤醒恢复验收

状态：已完成。验收日期：2026-09-23。

## 目标

完成 MVP-14：PC 在没有文件传输时进入一次正常睡眠并唤醒；PhoneBridge Windows 客户端恢复后能够重新验证当前共享中的 Samsung，保持唯一 P:/桌面客户端/rclone，没有僵尸资源或目录基线变化。

## 范围

使用当前已安装的 Android `0.1.0` 和 Windows P1-024 本地预览版。睡眠前记录唯一 P:/进程、目录清单、配对记录和 Windows 电源事件基线；手机保持已明确启动的 Music 前台共享。PC 正常睡眠后由用户正常唤醒，不在睡眠期间传输文件。唤醒后从系统恢复时间起 90 秒内应恢复或保持唯一 P:，目录清单一致；若 Windows 保留原挂载，也必须通过健康检查并实际读取，不能只看盘符存在。

## 不做什么

不要求睡眠期间传输，不制造待上传缓存，不休眠、不重启、不修改电源计划或 BIOS，不测试 Modern Standby 长时耗电、网络待机、多设备或大文件。只有复现并定位产品缺陷时才改代码。

## 涉及文件

- `docs/PRODUCT.md`、`docs/TESTING.md` 与本任务验收记录。
- 只有复现真实恢复缺陷时才修改 Windows 生命周期实现。

## 实现

预检已完成：`powercfg /a` 确认本机支持传统待机 S3；不支持 S0 低电量待机和混合睡眠。`powercfg /requests` 需要管理员权限，未为本任务提权或修改电源设置。

没有修改产品代码。ADB 自动开始 Samsung Music 共享，Windows 安装版 6.034 秒挂载唯一 P:。睡眠前 P: 顶层为 2 项，规范清单 SHA-256 为 `08B1BDD1639BB98723357062CB97FCA77EDA505DC12DF54458B4AFF24DFAB851`；桌面客户端、rclone、P: 均为 1。没有文件传输或待上传。

Windows 系统日志确认本机在 `2026-09-23 09:03:39.946 +08:00` 进入 S3，并在 `09:06:18.603 +08:00` 由电源按钮唤醒，实际睡眠 158.656 秒。睡眠期间发现候选消失，但原桌面进程、rclone 和 P: 保持；唤醒后 mDNS 候选恢复，客户端先记录一次健康失败，随后在 `09:06:23.152 +08:00` 恢复健康。

## 测试

从 Power-Troubleshooter 恢复事件起 4.550 秒恢复健康，低于预设 90 秒。唤醒后实际读取 P:：顶层仍为 2 项，规范清单 SHA-256 与基线一致；读取 `.thumbnails\\.database_uuid` 得到 36 字节，SHA-256 为 `1193D1082C29D7BC31D949054301393B5420E4473D4DB779DBD44160C95B0359`。原桌面 PID `27136` 和 rclone PID `20988` 均未更换，且桌面、rclone、P: 始终各一个；保存的两份配对记录及存储锁散列未变化。

## 验收结果

通过。传统 S3 睡眠 158.656 秒后，原挂载在 4.550 秒内恢复健康并完成实际文件读取，没有僵尸、重复进程、重复盘符或目录变化。结束时用 ADB 停止实验 App，Windows 自动卸载；最终手机共享进程/8273、P:、rclone 和桌面客户端均不存在。完整记录见 [P1-029 验收](../../audit/P1-029-VALIDATION.md)。
