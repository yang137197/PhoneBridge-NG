# P1-015 Windows 手动地址排障入口

状态：已完成限定任务。2026-09-21。

## 目标

在 mDNS 被路由器、VLAN 或 Windows 网络策略阻断时，为已有受保护配对记录提供明确的手动 IP/端口排障入口，同时保持证书身份绑定和单一活动挂载边界。

## 范围

先核对现有 `CandidateParser.TryManual`、Connection 严格 TLS 流程和 Android 实际端口展示能力，再设计 WPF 中英文输入、校验、临时候选生命周期和错误提示。手动地址只能提供路由位置，连接仍必须使用已保存 CA、受保护凭据、设备身份、`share_ready` 和模式校验；输入不持久化、不写日志、不进入诊断包。

## 不做什么

不接受 URL、域名、用户名、密码、Token、证书跳过参数或任意 rclone 参数；不把手动地址视为身份，不允许 HTTP 降级或错误证书继续。不实现多设备同时挂载、永久地址簿、远程互联网访问、UPnP、Tailscale、安装器或模式设置。若首次配对需要当前界面无法安全取得的配对端口/身份字段，先记录证据并拆分后续任务，不猜默认端口或削弱协议。

## 涉及文件

限定在 Windows Desktop/Discovery/Connection 的必要组合、资源、测试和项目文档；除非实测证明 Android 必须显示非秘密连接信息，否则不修改 Android。

## 实现

新增按已保存 `device_id` 隔离的 `ManualEndpointSession`。WPF 提供中英文 IP、端口、使用和清除入口；只接受严格字面地址与规范十进制端口。手动端点不进入发现注册表或配对存储，自动候选存在时去重并优先使用，缺少匹配候选时供当前进程重连回退。所有连接继续复用保存 CA、受保护凭据及严格 session 校验。日志只记录固定添加/移除/失败枚举。

## 测试

Release 构建 0 warnings/0 errors；271/271 项 Windows 测试通过。新增测试覆盖 IPv4/IPv6、端口边界、URL/域名/空白拒绝、记录隔离、去重/清除、无 mDNS 回退和固定日志字段。既有 Connection 测试继续覆盖错误 CA、SAN、设备身份与模式拒绝。Samsung 真机先验证错误端口不产生盘符，再在 UDP 5353 被阻断、只有离线保存记录时通过手动地址挂载；Wi-Fi 中断后安全卸载，恢复后仍无 mDNS 候选但自动恢复同一 P:。日志扫描无输入或认证资料。

## 验收结果

限定功能通过，Windows 与 Android 最终资源清理通过。首次配对仍要求 mDNS 配对广告；实际 IPv6 手动连接和手机地址变化后的人工更新未实测。证据见 [P1-015 验收](../../audit/P1-015-VALIDATION.md)。当时的唯一下一任务为 [P1-016 1 GB 双向传输与中断完整性](P1-016-1gb-transfer-integrity.md)。
