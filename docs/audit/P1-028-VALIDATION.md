# P1-028 手机 IP 变化恢复验收

日期：2026-09-22。结果：通过。设备为 Samsung SM-S9180/API 36，使用 Android `0.1.0` 和 P1-024 Windows 最终安装版；切换期间没有文件传输。

## 基线

PC 为 `192.168.100.216/24`。手机连接已保存的 `Catwrt_5G`，地址为 `192.168.100.238/24`。ADB 自动开始 Music 共享，Windows 安装版 5.069 秒挂载唯一 P:；顶层 2 项的规范清单 SHA-256 为 `08B1BDD1639BB98723357062CB97FCA77EDA505DC12DF54458B4AFF24DFAB851`。

验收前固定：必须发生真实 IPv4 变化；不得用手动地址替代 mDNS；新地址可用起 90 秒内恢复原 P:；保存身份、目录基线和进程唯一性保持。

## 地址变化与恢复

手机从同一路由器的 `Catwrt_5G` 切换到已保存的 `Catwrt`，获得 `192.168.100.171/24`。旧地址 8273 随后不可达，新地址 8273 可达。Windows 日志记录：

- 切换后约 5.5 秒，mDNS 候选 `DiscoveryChanged/Updated`，数量仍为 1。
- 原连接连续三次健康检查失败，约 30.6 秒进入 `Lost`。
- P: 在 32.718 秒消失；原 rclone 正常退出。
- 随即使用更新候选连接，P: 在 34.117 秒恢复；日志在约 34.3 秒记录 `ConnectionCompleted/Mounted`。
- 新会话 rclone 配置回读的端点主机为 `192.168.100.171`，之后健康检查持续成功。

全过程只有一个 `PhoneBridge.Desktop`、一个 rclone 和一个 P:，没有手动地址覆盖。恢复后 P: 顶层仍为 2 项，清单 SHA-256 与基线一致。两份 Windows `.pairing` 记录和 `.store.lock` 的散列与 P1-026 基线一致，没有重新配对或改写保存身份。

## 清理与边界

验收后明确停止共享，P: 在 24.557 秒内安全卸载。手机恢复原 `Catwrt_5G` 和 `192.168.100.238`；最终 8273、P:、Windows 客户端和 rclone 均不存在。原始结构化证据保存在被忽略的 `.audit/runs/P1-028/`。

没有修改产品代码，因此没有重复 Windows 279/279 或 Android 123 个 Gradle task。结论覆盖同一路由器两个已保存 SSID 间的真实 IPv4 变化、mDNS 更新、严格身份复用和自动恢复；不外推跨子网、蜂窝、VPN、睡眠或传输中切换。
