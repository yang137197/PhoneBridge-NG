# P1-015 Windows 手动地址排障入口

日期：2026-09-21。结果：实现与限定链路通过，最终资源清理通过。

## 设计与实现

手动地址只绑定已有受保护配对记录，不创建发现候选或修改凭据。输入仅接受严格 IPv4/IPv6 字面量与规范十进制 1–65535 端口；URL、域名、回环、任意地址、组播、空白和非规范端口失败关闭。地址只存在当前桌面进程内，清除或退出后消失。

连接、删除、撤销和恢复继续调用既有 `ConnectionClient`，因此保存 CA、原生 SAN、受保护 Token、设备/客户端身份、`share_ready` 和模式核对不变。自动发现端点与临时端点按值去重；恢复优先使用匹配的 PairedV3 候选，没有候选时才回退到同一 `device_id` 的临时端点。首次配对端口是动态值，当前表单缺少 PAKE 所需身份与窗口材料，所以不支持手动首次配对。

## Samsung 真机

设备为 Samsung SM-S9180、Android 16，使用已有受保护配对记录。先验证错误端口连接失败，没有 P: 或 rclone；正确端口通过严格验证后挂载。

随后用两条专用 Windows 防火墙规则临时阻断 UDP 5353，并清除 DNS 客户端缓存；TCP 文件端口仍可达。重启桌面客户端后列表只有 Redmi 与 Samsung 两条离线保存记录，mDNS 候选为 0。选择 Samsung 保存记录、输入手动地址后成功挂载 P: 并读取根目录。

保持 UDP 5353 阻断，关闭手机 Wi-Fi 后客户端在约 34 秒完成三次健康失败和安全卸载，rclone 退出；恢复 Wi-Fi 后地址未变化，客户端只凭内存端点重新验证并自动恢复同一 P:，界面报告“已恢复同一台手机和原盘符”。全程没有 mDNS 候选。

清除临时端点时当前 P: 保持；退出并重启后地址框为空、清除按钮禁用，证明地址未持久化。实际产品日志共 101 行，全部为有效 JSON；5 条 `ManualEndpointChanged` 只有固定事件/结果/状态字段，测试 IP、错误端口及 Authorization/Bearer/Basic/Token/Password 模式均为 0 命中。诊断包只复制这些白名单日志，因此不会新增手动输入。

测试结束后安全卸载，P:、rclone 和桌面进程均消失；防火墙辅助脚本写入清理标记，两条专用规则回读为不存在。用户在手机明确停止共享后，Android 服务列表为空、活动通知键中没有 PhoneBridge、端口 8273 不可达、PhoneBridge WakeLock 不存在。系统保留的应用进程 CPU 为 0，且没有服务、通知、端口或锁，不是后台共享。
