# P2-019 — v0.2.4 安装候选与底栏实机验收

状态：进行中。日期：2026-09-28。

启动回读：GitHub Latest 为正式 `v0.2.3`，非草稿、非预发布；标签提交为 `927135e3b51a901076b067378658e708ae805d75`，六项资产齐全且本地正式镜像的 SHA-256 与 GitHub 资产摘要逐项一致。

## 目标

生成可核验的 v0.2.4 安装候选，以当前正式 GitHub Latest 为动态升级基线，验证真实 Windows 底栏及资源管理器在无挂载、单设备和多设备状态下的设备名称与盘符对应关系。

## 范围

- 开始时重新回读 GitHub Latest；若不再是正式 `v0.2.3`，停止并重定升级基线。
- 统一前移 Windows、Android、安装说明和交付脚本版本，使用既有正式 Android 签名身份生成六项候选并核对摘要。
- 从正式基线原位升级，确认配对、设备备注、访问模式、盘符偏好和已有缓存保持。
- 实机验证无挂载时的两项默认提示、单设备备注/原名与盘符、两台设备合并显示，以及任一设备断开后另一设备仍保持正确。
- 把资源管理器显示名收敛为“设备备注或设备名 (盘符)”，同时保持设备会话、盘符与缓存隔离。
- 核对挂载中、缓存恢复、安全卸载和卸载失败不会被稳定连接汇总错误覆盖。

## 不做什么

- 不修改连接协议、挂载生命周期、盘符分配或自动重连策略。
- 不重复无关的大文件、睡眠、手机重启或完整功能矩阵。
- 不推送、不打标签、不创建 GitHub Release；正式发布和全新机器验收继续作为独立任务。

## 停止条件

正式基线或资产摘要异常、签名不连续、升级丢失状态、底栏设备与盘符映射错误、错误身份被显示为已连接，或安全状态提示被覆盖时立即停止并保留证据。

## 验收结果

首个候选已停止验收并作废。正式 `v0.2.3` 原位升级至首个 `v0.2.4` 候选后，Windows/Android 版本、正式 Android 签名身份、配对记录、访问模式和缓存均保持；无挂载及单设备挂载底栏通过，设备备注从 `M2012K11AC` 改为 `K40` 后底栏即时更新，断开后盘符与 rclone 均退出。

随后发现阻断缺陷：约五分钟真实连接期间，Android 共享服务、TCP 8273 和系统 NSD advertiser 均保持活动，Windows 仍因周期重建 DeviceWatcher 未重新枚举而连续两轮撤销候选；用户断开后设备卡显示离线，刷新无法恢复，连接按钮因没有端点而不执行。该现象否定了 P1-001 仅 32 秒在线样本对长期重枚举稳定性的覆盖，首个候选不得发布。

第一次修复版安装后再次发现：手机已在共享时启动 Windows，新 watcher 仍可能从零开始无法枚举，因此仅保留当前进程端点不足。锁屏现场还确认：设备被撤销前约两秒严格健康检查仍成功，但 Windows 收到原生 `Removed` 后立即撤销候选；用户确认 PhoneBridge NG 此前一直为“无限制”，解锁后同一广告重新出现并成功连接。因此当前证据支持“发现事件被误当离线”，不支持把本次故障归因于未配置电池豁免。

当前修复边界扩展为：保留周期重枚举和两轮缺失清理；已配对候选在第二轮缺失或收到原生 `Removed` 时，先执行保存 CA、凭据及严格 session 校验，认证仍在线则保留，校验失败才撤销；无效元数据与未配对候选不放宽；刷新不再预先清空候选；最后一次严格认证成功的规范 IP/端口随配对记录受 DPAPI 保护并跨进程保留，只作寻址回退，每次连接仍重新认证，地址变化仅在新端点认证成功后替换，删除本地配对时清除。用户手动排障地址仍只在当前进程存在。

安装修复版后，K40 锁屏期间持续 6 分钟以上共取得 85 次健康检查成功、0 次失败、0 次错误候选移除，`E:` 与单一 rclone 始终保持；断开后盘符和 rclone 正常退出。手机继续锁屏且新进程首次发现数量为 0 时，Windows 从 DPAPI 记录恢复 `192.168.5.3:8273`，用户可直接连接并重新挂载 `E:`，证明冷启动不再依赖当次 mDNS。该次现场也发现设备卡片在无当次候选时仍显示“离线”，没有显示实际已用于连接的保存地址；显示层已改为优先展示当前发现地址，缺失时展示最后一次已认证地址，不改变认证或连接选择。
