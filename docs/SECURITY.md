# 安全与数据完整性要求

状态：当前正式第三方侧载版本已实现本文件的主要产品控制：v3 配对、严格 TLS、DPAPI/Android Keystore、每请求授权、共享根边界、三种访问模式、安全写入/删除确认、缓存归属和脱敏诊断。证据来自 P1-005 至 P1-023 的分阶段验收及 P1-042 的正式签名真机链路；这不是对原始上游安全性的认可，也不是独立密码学审计或第三方安全认证。依据 [AGENTS](../AGENTS.md) 及 [UPSTREAM_AUDIT](UPSTREAM_AUDIT.md)。

## 1. 信任边界

保护对象为手机文件、设备身份、长期凭据、私钥与尚未上传的数据。局域网、mDNS TXT、IP、设备名称、远端错误文本及文件名均可能不可信。

文件操作需要同时通过系统权限、应用授权模式、共享路径边界。成功认证不授予共享根之外的访问权限；拒绝未知协议/身份/路径，不能用“继续尝试”放宽保护。

## 2. 身份、凭据与传输

- 首次配对让用户确认真实设备身份；ADR-017/PAIRING 的 PAKE、120 秒窗口、5 次尝试、每电脑随机 token 和手机明确批准已由 P1-007/008 实现并完成限定验证。
- 后续每次认证/状态请求和 rclone 的每条文件传输连接均校验证书绑定。获取证书失败、证书改变、身份不匹配均拒绝，不先发送长期凭据。
- 证书改变明确提示“设备身份发生变化，需要重新配对。”不能仅靠 mDNS 的同名设备或“接受并继续”静默更新绑定。
- 正式版本禁止 `--no-check-certificate`、`CERT_NONE` 或 HTTP 回退；手动连接、托盘和自动重连适用相同规则。
- ADR-017 选择当前用户 DPAPI 保护 Windows 整条记录，Android Keystore AES-GCM 保护 token 验证值和元数据；保存失败不继续授权。Keystore 是密钥容器，不能把 SharedPreferences 明文标成“已进入 Keystore”。[Android 官方说明](https://developer.android.com/privacy-and-security/keystore)
- 普通设置 JSON、日志、URL、可见命令行、崩溃报告、截图、仓库不得包含秘密；已认证 HTTPS 的受限授权请求体不属于明文持久化。rclone obscure 的可逆混淆不满足长期安全保存要求。
- ADR-014 的 TLS 路线、ADR-017 生命周期、两端受保护记录和网络授权已接入产品。进程环境不能视为保险库；凭据只从 DPAPI Active 记录短暂提供给受限 rclone 子进程。P1-014 已验证固定字段日志与白名单诊断包不含认证资料、设备地址或文件路径。

历史边界：P0-003 只在隔离环境观察上游开发态自签证书行为，不能作为安全验收。原始客户端的明文凭据路径没有引入 NG；当前产品使用独立应用 ID、v3 配对和受保护记录，不迁移上游密码。

## 3. 文件与授权模式

| 操作 | 只读模式 | 安全模式（默认） | 完全读写模式 |
| --- | --- | --- | --- |
| 列目录、打开、下载 | 允许 | 允许 | 允许 |
| 上传、新目录、重命名 | 拒绝 | 允许，但须遵守完整性和覆盖规则 | 允许，仍遵守完整性和路径边界 |
| 删除 | 拒绝 | 必须有针对该操作的明确确认，否则拒绝 | 用户已选择该模式时允许；仍禁止越界及共享根破坏 |

只读不能仅是 UI 隐藏按钮，安全模式也不能只依赖 Explorer 弹窗。服务器必须拒绝未授权请求。P1-009 的确认绑定当前服务实例、client_id、规范路径和完整目标树快照，30 秒后过期且执行尝试即消费；过期、重放、目录内容或目标变化均拒绝。安全模式下 PUT/MOVE/COPY 目标必须不存在，不得通过覆盖达到绕过删除保护的效果。

路径必须按规范解码并验证真实归属；拒绝越界、畸形编码、危险符号链接及对共享根的破坏性操作。不能字符串前缀比较后放行兄弟目录，不能把非法路径映射回根目录。重命名/复制须分别检查源和目标。

上传不得在确认完整请求前破坏原文件；短写、断网、磁盘满、冲突及进程退出须保持可解释的结果。禁止半文件被报告为成功；重连重试不能意外覆盖用户后续修改。回收站只预留未来实现边界，本阶段不假装已具有回收能力。

## 4. 缓存与进程

每个设备的挂载、盘符、缓存及待上传数据有明确归属。避免重复 rclone 使用同一缓存，避免未读 stdout/stderr 堵塞；有界停止并保留必要恢复信息。清缓存前确认数据已上传或用户明确处理丢弃，不能将离线卸载当作上传完成。

更换证书/设备身份后，不得把旧设备的待上传数据自动推送给新身份。缓存限额与磁盘满处理需真实测试，不能只设置 max-age。

## 5. 日志与诊断

记录发现、验证结果、挂载/卸载、rclone 退出、WinFsp 状态、网络变化及重连。日志采用轮转和安全字段；不记录密码/Token/认证 Header/私钥/文件内容。异常信息、文件名、设备名同样做脱敏/转义，防止第三方错误文本夹带秘密。

诊断包只包含必要的版本、非秘密配置、事件和状态；导出前脱敏，不自动上传。用户文件内容不作为诊断资料。实际设备地址/文件路径若非必要不写入可分发证据。

## P1-007 正式 Android 授权边界（历史阶段）

新 org.phonebridge.ng 与实验 com.phonebridge 隔离；启动复用 Keystore CA 并绑定配对库，材料缺失/不一致不自动新建身份或迁移旧密码。只有经过 PAKE 确认的 grant 可提交一次待批准请求；手机本地批准并可靠保存后，长期 token 才能请求 session/当时的只读文件。每请求重新授权，撤销关闭所属活动流。P1-007 阶段暂拒绝所有写操作；P1-009 后续实现安全写入与删除确认，P1-023 完成三种模式入口。

严格 HTTP 入口与固定错误不记录请求/异常原文；临时代码受 FLAG_SECURE 保护，离开前台即关闭窗口。没有 HTML 目录列表，GET 目录拒绝，PROPFIND 使用已验证 XML 编码。TLS 只启用 1.2/1.3；测试宿主采用受确认 CA 的严格证书链与地址校验，不使用任意证书接受回调。新路径不等于旧实验 APK 风险已全部关闭。

存储失败可先终止已认证连接，所以客户端可能只见断开而不是 503；此时绝不能显示撤销成功。mDNS 发布失败/系统缓存延迟不能建立任何信任；只有活窗口和实际协议决定是否接受配对。后续 P1-008 已完成 Windows 产品网络入口，P1-009 完成安全模式写屏障，P1-010/011 完成锁屏及恢复，P1-014 完成日志/诊断包；各项结论仍限于对应验收范围。
