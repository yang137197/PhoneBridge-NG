# P1-026 Android 重启恢复验收

状态：已完成。验收日期：2026-09-22。

## 目标

完成 MVP-04：Samsung 在没有文件传输进行时实际重启，用户正常解锁并重新开始共享后，Windows 能按原配对恢复唯一盘符，既有文件保持不变且两端无僵尸资源。

## 范围

使用已安装的 Android `0.1.0` 和 Windows 本地预览版。重启前建立一个只读基线，确认单一 P:/rclone 和无待上传；执行一次正常 Android 重启。重启期间只验证 Windows 安全离线，不要求继续传输。用户解锁后由 ADB 自动打开 PhoneBridge、复用 Music 并开始共享；Windows 自动恢复同一已配对设备和原盘符，重新读取基线并核对进程唯一性。

## 不做什么

不在重启期间复制文件，不清除手机、不重装 APK、不修改系统安全设置，不测试 Windows 重启、PC 睡眠、IP 变化、大目录、多设备或新的后台自启动功能。若系统要求锁屏凭据，只由用户正常解锁，ADB 不绕过设备锁。

## 涉及文件

- 原则上只新增本任务验收记录并更新 MVP-04 状态。
- 只有复现真实产品缺陷且确认根因后才修改对应 Android/Windows 代码。

## 实现

产品代码目前无需预改。重启前已核对 Samsung SM-S9180/API 36、Android `0.1.0`、Windows 最终安装版、两份配对记录及用户保持关闭的 Windows 自启动偏好。ADB 自动开始 Music 共享，安装版 6.192 秒挂载 P:；记录顶层清单 SHA-256 `EEFDA3D67FFE99879C960245A5CB20F0DC6AE82BC55551B6C3648B2C64E02D94`，并选择一个 36 字节非空既有文件作为恢复样本，SHA-256 为 `1193D1082C29D7BC31D949054301393B5420E4473D4DB779DBD44160C95B0359`。完整相对路径只保存在被忽略的本地预检证据中，不写入产品文档或日志。

用户确认后执行一次正常 Samsung 重启。ADB 先观察到设备断开，再在 52 秒后观察到系统启动完成；内核 boot ID 从 `e72751d0-6097-48fd-b5bd-60705aa9ca89` 变为 `31f9cff1-24c6-4b45-bad6-9800a2b03f9b`。用户完成首次解锁后，ADB 自动打开 PhoneBridge 并启动 Music 共享；`LY` 配对、安全模式、目录选择、前台服务和 8273 均恢复。Windows 最终安装版以保存身份重新连接，7.289 秒挂载 P:，全程只有一个桌面客户端和一个 rclone。

## 测试

重启前基线通过：单一 P:、一个桌面客户端和一个 rclone；只读取目录和样本，没有写入手机。重启后顶层项目数仍为 2、清单 SHA-256 相同；36 字节样本长度与 SHA-256 相同；Windows 的两份 `.pairing` 记录和 `.store.lock` 散列均未变化。预检和重启后证据分别保存在 `.audit/runs/P1-026/preflight.json` 与 `postreboot.json`。

## 验收结果

通过。MVP-04 的实际 Android 重启、首次解锁、用户重新共享、原身份恢复、唯一盘符和既有文件完整性均取得真机证据。重启期间没有文件传输；Windows 客户端处理活动连接丢失的安全卸载与自动恢复已由 P1-010/P1-011 直接验证，本任务不重复该故障注入。最终共享停止，Android 前台服务、8273、WakeLock、P:、rclone 和 Windows 客户端均不存在。完整记录见 [P1-026 验收](../../audit/P1-026-VALIDATION.md)。
