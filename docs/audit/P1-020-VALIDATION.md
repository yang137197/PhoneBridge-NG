# P1-020 20 GB 双向边界完整性验收

日期：2026-09-22  
结果：通过限定范围。

## 环境与边界

- Windows 11、WinFsp、项目固定 rclone 1.75.1、Release Windows 客户端。
- Samsung SM-S9180，Android 16/API 36，共享根为 `Music`。
- 两个样本均为精确十进制 20,000,000,000 字节；手机样本每 1,000,000 字节段写入不同标记。
- 预检时手机共享存储约 210.7 GB 可用，PC 约 190.4 GB 可用；P:、rclone、桌面进程和旧任务目录均不存在。
- 本轮只验证 20 GB 双向边界、原子提交、缓存清零、单实例与安全卸载；不包含 Explorer 人工拖放、播放、随机 Seek、磁盘满、重启或睡眠期间传输。

## 手机到 PC

Android 专用脚本在固定测试目录生成精确 20,000,000,000 字节文件；错误目标会以退出码 2 拒绝且不创建文件，完成后没有临时文件。手机独立 SHA-256 为 `f0149f07ccd93b301883c0e7e93ab662705f06dbd177651b9c9d75dae3ce7d82`。

通过 P: 流式复制到 Windows 共用时 437.841 秒。Windows 最终长度为 20,000,000,000 字节，独立计算 SHA-256 用时 32.706 秒，结果与手机完全一致。传输期间 P: 持续存在，桌面客户端和 rclone 始终各一个。

## PC 到手机

Windows 以种子 5251120 流式生成并同步散列独立样本，用时 266.871 秒；长度为 20,000,000,000 字节，SHA-256 为 `e80a39bfe8e81342407323c668406e5c8815995c1886dde1f6e1ab875f9a1e8d`。

写入 P: 共用时 473.964 秒。句柄关闭后 VFS 数据文件为完整 20,000,000,000 字节，元数据为 `Dirty: true`；Android 只存在一个持续增长的 `.phonebridge-upload-*.part`，最终目标尚未出现。后台继续上传 212.628 秒后，元数据变为 `Dirty: false`、临时文件消失，最终文件以精确 20,000,000,000 字节原子出现。Android 独立 `sha256sum` 用时 49.378 秒，结果与 Windows 源完全一致。

## 卸载与清理

用户通过 Windows 客户端正常卸载。回读确认 P: 不存在、rclone 为 0、桌面客户端仍运行，且缓存元数据在清理前明确为 `Dirty: false`。随后只删除两份本地 20 GB 样本、对应干净 VFS 数据/元数据、手机 `Music/PhoneBridge-P1-020` 专用目录及生成辅助脚本。

用户在手机端正常停止共享后，Android `SharingService`、8273 监听和当前 `PhoneBridge-NG:sharing` WakeLock 均不存在。最终关闭空闲 Windows 客户端后，P:、rclone、桌面进程均为 0。结构化现场摘要见[证据文件](p1-020/large-file-live.json)。

## 自动检查与限制

本任务新增的 Android 生成脚本通过 shell 语法、错误目标拒绝、精确长度、分段内容和临时文件清理检查。产品代码未改变，因此没有重复运行 P1-019 已通过的 279 项 Windows 回归。

DATA-01 的十进制 20 GB 双向长度、独立哈希和真正落盘获得 Samsung 真机证据。人工 Explorer 拖放、视频播放与随机 Seek、磁盘满、手机重启、PC 睡眠和多设备同时挂载仍未验证；这些限制不能据此标记为 MVP 完成。唯一下一任务为 P1-021 视频播放与随机 Seek。
