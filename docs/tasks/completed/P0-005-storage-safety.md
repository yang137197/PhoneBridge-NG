# P0-005 共享路径与上传提交安全

- 状态：已完成本任务限定范围；Phase 0 与完整产品未完成
- 目标：消除原版越界/根目录破坏和直接覆盖上传造成的数据损失风险，使下一阶段隔离设备验证有可靠文件安全基础。
- 范围：在 P0-004 基础上独立最小修复；共享路径解析、拒绝根/范围外写入和删除、上传暂存/完整长度验证/成功后原子提交、失败保留旧文件；对应真实协议回归与复制验证。
- 不做什么：不启动 WPF 或大规模 UI 重写，不接主手机，不把路径保护当作安全模式删除确认或正式身份体系已经实现。
- 涉及文件：独立 Android 修复副本、后续补丁、单元/真实协议测试、验收与来源记录。

## 实现

已在专用 PhoneBridgeP0 模拟器复现：普通/双重编码路径读取到 Download-sibling 哨兵，范围外路径回退到根列表；短正文覆盖将 32,768 字节旧文件截成 100 字节，返回 500。证据暂存 `.audit/runs/P0-005/unsafe-baseline.json`，P0-003/P0-004 产物保持不变。

独立 `.audit/p0-005-worktree` 修复已完成。请求路径只解析一次；持有目录描述符，以 NOFOLLOW 打开每层目录并校验句柄类型，拒绝链接、特殊文件和根修改；修正 Destination 与选择目录缺失时的全盘回退。上传先写排他临时文件，精确读取、同步数据后重命名提交；保留状态不明的历史暂存文件。失败启动路径提前进入前台服务并正确停止，避免启动超时崩溃。

累计补丁保存于 `android/patches/P0-005-storage-safety.patch`，基于原始提交并包含 P0-004，不叠加应用；来源/许可与逐文件散列保留。

## 测试

20 个单元、63 项存储 HTTPS、34 项数据流 HTTPS 通过；Android 原生测试 11 通过、1 因硬链接样本被 SELinux 拒绝而跳过。进程终止后旧文件不变、暂存保留；缺失/未知共享选择两项通过。实际 P: 非重复 100 MB 双向哈希一致，创建/重命名及正常卸载通过。资源管理器视图 15 项，人工打开/拖放未确认。
