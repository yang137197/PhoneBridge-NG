# P2-011 — v0.2.2 正式候选、升级与发布

状态：进行中。日期：2026-09-28。

## 目标

把已完成的 v0.2.1/v0.2.2 改动收口为使用既有长期 Android 身份的正式候选，完成从最近正式 Release 的原位升级门禁和全新机器配对验收准备；门禁通过后发布 GitHub `v0.2.2`。

## 范围

- 实时确定前一正式 Release、提交与六项资产摘要。
- 推送开发分支，生成 Windows 安装器、长期签名 Android APK、对应源码、README、散列和 manifest。
- 从前一正式版本原位升级，回读版本、签名、配对、设备备注/盘符设置、连接、挂载、停止共享、断开和资源清理。
- 准备全新 Windows 机器与 Android 全新安装后的配对、备注盘名、Auto 盘符和停止共享验收。
- 通过全部强制门禁后，创建精确标签和 GitHub Release，上传并回读六项资产。

## 不做什么

- 不用 r22 UI 预览、Debug APK 或旧制品冒充正式候选。
- 不创建或替换长期签名身份，不输出签名密码或私钥。
- 不用全新安装替代正式版本升级，不在失败时清空数据绕过。
- 不重复无关的大文件、睡眠或性能矩阵。

## 当前实时基线

- 前一正式 Release：`v0.2.0`，非草稿、非预发布，发布时间 `2026-09-26T07:39:26Z`。
- 标签提交：`60c52b729f2052fa933870bfc175df01d78f17be`。
- 六项 GitHub 资产均为 uploaded；安装器、APK、源码、README、SHA256SUMS 和 manifest 的摘要与 P2-008 记录一致。
- 开发分支 `codex/v0.2.1-v0.2.2` 已推送；正式标签和 Release 尚未创建。

## 停止条件

- 长期签名身份或密码不可用、签名摘要改变。
- 候选制品/源码/许可/散列/manifest 不一致。
- Windows 或 Android 的 `v0.2.0 → v0.2.2` 原位升级、配对/设置保持、基础连接或安全断开失败。
- 全新机器验收前置条件不满足时，只保留候选和操作清单，不声明全新机器通过。
