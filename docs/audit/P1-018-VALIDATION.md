# P1-018 10 GB 双向传输完整性验收

日期：2026-09-22  
结果：通过限定范围；另发现一个 Windows 重启恢复状态缺陷，转入 P1-019。

## 环境与边界

- Windows 11、WinFsp、项目固定 rclone 1.75.1、Release Windows 客户端。
- Samsung SM-S9180，Android API 36，共享根为 `Music`。
- 两个样本均为精确十进制 10,000,000,000 字节；手机样本每 1,000,000 字节段含不同标记。
- 文件通过 P: 挂载路径复制。本轮不包含人工 Explorer 拖放、20 GB、播放、随机 Seek或磁盘满。

## 手机到 PC

手机独立生成并计算 SHA-256：`b535a5b0072feff9259a8af8e60c68cea180679c8d8abb58ab36dae2f22f336c`。通过 P: 无缓冲复制耗时 237,373 ms；Windows 最终文件精确为 10,000,000,000 字节，独立 SHA-256 相同。传输期间桌面端持续响应，P: 存在且只有一个 rclone。

## PC 到手机与缺陷修复

PC 流式生成并二次校验的 SHA-256 为 `3ba013d4185d6b0448b49222e91b9bebe1377b90ec5b2fd1c108e69b1491a224`。

首次上传没有创建手机暂存文件，缓存持续 `Dirty: true`。源码和现场现象确认 Android PUT 的 8 GiB 上限在读取正文前拒绝 10,000,000,000 字节。上限改为项目要求的十进制 20,000,000,000 字节，并增加 10/20 GB 接受和超限失败关闭测试。

修复后暂存文件开始增长，但约 6.34 GB 后被中止并重新开始。固定 120 秒请求截止时间会终止仍在持续进展的上传；修正为连续 120 秒无进展才中止，正文持续到达时每 30 秒续期。最终 Android 文件精确为 10,000,000,000 字节，Android `sha256sum` 与 PC 源相同；缓存元数据为 `Dirty: false`、`Fingerprint: 10000000000`。

覆盖安装中止旧进程后遗留一个不再增长的 5,546,274,816 字节暂存文件。确认最终文件哈希后按精确名称删除，最终文件保持不变，暂存文件计数归零。

## 重启恢复观察

测试期间 PC 被重启。稳定缓存命名空间保留了完整 10 GB 缓存；恢复连接后 rclone 成功提交并清除 `Dirty`。但首次连接在 30 秒挂载等待期后显示超时，而上传继续约至连接开始后 149.7 秒才由缓存元数据确认完成；第二次连接立即成功出现 P:。这证明数据恢复成功，也证明当前界面把“大脏缓存恢复中”错误报告为挂载失败。该问题未在本任务扩展修复，转入 P1-019。

## 自动验证与清理

最终 Android Debug/Release/test APK、17/17 JVM 单元测试和 Debug/Release Lint 通过，共 123 个 Gradle task 成功。手机任务目录、PC 两个 10 GB 样本和两个任务缓存文件已删除。安全卸载后 P: 与 rclone 消失；用户停止共享后，Android 服务、活动通知、PhoneBridge Wake Lock 和 8273 监听均不存在，桌面端也已退出。
