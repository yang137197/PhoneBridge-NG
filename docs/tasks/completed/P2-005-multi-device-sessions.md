# P2-005 — 按设备隔离的多会话核心

状态：已完成。日期：2026-09-26。

## 目标

将 Windows 全局唯一连接所有权改为按 `device_id` 隔离的设备会话，并以 Samsung 与 Redmi 同时挂载两个不同盘符、断开一台不影响另一台作为最小真实通过线。

## 已实现

- 每个设备会话独立拥有连接客户端、挂载管理器、盘符预留、rclone/RC、会话目录、操作取消令牌、健康检查、重连状态及非身份日志上下文。
- 轻量会话协调器只管理会话集合、进程内盘符冲突、应用退出和聚合状态；不同设备的网络和挂载操作不经过全局长时锁。
- Windows 设备卡片的配对、连接、打开、断开、移除、取消和监督只作用于所选设备；一个设备断线不会停止另一设备。
- 既有按证书身份隔离的 VFS 缓存根保持稳定，避免多会话目录重构遗失可恢复缓存。
- 日志 schema 2 使用进程内会话序号区分上下文，不记录设备身份、地址、盘符或路径。

## 已验证

- Windows locked restore、Release 构建 0 警告/0 错误，294/294 测试通过；新增退出协调测试确认一个会话操作失败不阻止其他会话取消、停止和释放盘符。
- r20 Android 构建与 lint 共 39 个任务成功；同一 APK 安装到 Samsung 与 Redmi。
- 正确的 r20 Windows 隔离候选同时挂载 Redmi P: 与 Samsung E:，两个独立 rclone、RC 端口和设备会话目录均已回读确认。
- 两个盘符各完成一次小文件本机→手机、手机→本机回读，SHA-256 一致。
- 停止 Redmi 后其 rclone 退出；Samsung E: 保持可浏览并再次完成双向回读，SHA-256 一致。
- r20 日志 schema、会话序号和禁止身份字段扫描通过。完整证据见 [P2-005 验证](../../audit/P2-005-VALIDATION.md)。
- 托盘正常退出后桌面进程、全部 rclone 和 P:/E: 均清理，隔离配对记录保留。
