# P2-023 — v0.2.5 正式候选与升级验收

状态：已完成。日期：2026-09-29。

## 目标

把 P2-022 已通过的 Android 首次点击配对修复纳入版本递增的完整正式候选，并按开发规则 4.1 从当前最近的资产完整正式 Release 做两端原位升级验收。

## 范围

- 开始时实时解析最近一个非草稿、非预发布、资产完整的正式 Release，记录其标签、提交和资产 SHA-256；当前预期为 `v0.2.4`，但以实时结果为准。
- 将 Windows、Android、构建脚本和安装说明统一递增到 `0.2.5`；Android `versionCode` 递增且继续使用同一正式签名身份。
- 生成安装器、APK、对应源码 ZIP、README、SHA256SUMS 和 manifest，并核对文件集合、版本、签名和摘要。
- 在 Windows 与 Android 上先恢复真实 `V_prev` 正式资产及可回读配对/设置，再原位安装 `V_new` 候选。
- 验证配对与设置保持、首次点击配对修复、基础连接、文件访问和安全断开。

## 不做什么

- 不继续添加功能或修改无关模块。
- 不用 P2-022 的同版本定向候选代替正式版本递增或升级验收。
- 不推送分支、不创建标签或 GitHub Release；发布必须另行获得明确授权。
- 任一版本、签名、升级状态或制品一致性不符即停止。

## 涉及文件

- Android 与 Windows 版本源：`android/app/build.gradle.kts`、`windows/src/PhoneBridge.Desktop/PhoneBridge.Desktop.csproj`
- 交付脚本：`scripts/Build-LocalDelivery.ps1`、`scripts/New-SourceDelivery.ps1`、`scripts/Build-UiAcceptance.ps1`
- 更新策略测试：`android/app/src/test/java/org/phonebridge/ng/UpdatePolicyTests.kt`、`windows/tests/PhoneBridge.Desktop.Tests/UpdateServiceTests.cs`
- 安装说明及当前任务、验收、README 和交接文档

## 实现

已于 2026-09-29 实时回读 GitHub Latest Release：`v0.2.4`，非草稿、非预发布，发布时间 `2026-09-29T06:22:12Z`；注释标签剥离后提交为 `98e17a182ec61eb6d71382544c3d450a61c1f949`。六项资产均为 uploaded，本地 P2-021 下载副本的文件名、大小和 GitHub `digest` 逐项一致。

动态升级基线确定为 `V_prev=v0.2.4`。版本绑定已统一递增为 Windows/Android `0.2.5`、Android versionCode 7；历史任务和正式 Release 描述未做全局替换。

首版正式签名候选已生成，但在 `V_prev` 真实连接基线中发现卡片“断开”仍可能吞掉首次点击，因此该候选已停止升级验收，不作为最终候选。现场确认 E:、rclone 和会话均保持正常，诊断日志没有进入 `MountStateChanged/Stopping`，排除“后台卸载较慢”。只读 UI Automation 连续采样进一步确认“断开”按钮的运行时实例约每秒变化一次；根因是健康监督每秒进入和退出时都调用 `RebuildRows`，而该方法无条件替换 `Devices.ItemsSource`，导致鼠标按下与释放之间设备卡及按钮可能被销毁，WPF 不再产生 Click。

修复后，设备卡仅在可见数据确有变化时替换；后台健康监督不再被当作设备卡的用户操作忙碌状态。连接、断开等真实用户操作仍会立即更新卡片，且 P2-019 已有的用户操作与健康监督仲裁不变。

包含该修复的正式签名 r2 候选已生成于 `.audit/delivery/P2-023-v0.2.5-candidate-r2/output/`。Windows 安装器 SHA-256 为 `2A1209B9935BE2EA6A3DD3AC083A98F48E119801D99FCD616F5375BDA455DB2E`；Android APK SHA-256 为 `CEF0172E316B8F31C9A2B80389C83FDF51C6C86D29AB7CF73E8559FE1B77CEAB`。独立回读确认安装器产品版本 `0.2.5`，APK 包名 `org.phonebridge.ng`、versionCode 7、versionName 0.2.5、v2/v3 签名有效且唯一 signer SHA-256 为 `66FF69D71637D215C2F104DB95B93CC1F991FA1F23580F95AF3316B0763B14D4`；三项交付文件与 manifest、`SHA256SUMS.txt` 完全一致。
