# P1-028 手机 IP 变化恢复验收

状态：已完成。验收日期：2026-09-22。

## 目标

完成 MVP-13：Samsung 共享期间实际获得新的局域网 IPv4 地址后，Windows 通过 mDNS 找回同一已配对设备，以保存的 CA、设备身份和每电脑凭据重新验证，在不产生重复进程或盘符的前提下恢复原 P:。

## 范围

使用当前已安装的 Android `0.1.0` 和 Windows P1-024 本地预览版。先记录旧 IPv4、设备 ID、唯一 P:/客户端/rclone 和只读目录基线；在没有文件传输时让手机发生一次真实 IPv4 变化，并记录变化方式。旧地址失效后允许现有三次健康检查安全卸载；新 mDNS 候选必须匹配原 `device_id` 并通过严格 TLS/session 校验。新地址可用起 90 秒内应恢复唯一 P:，目录基线一致。

若 Wi-Fi 重连后 DHCP 仍分配原地址，结果记为未形成测试条件，不冒充 IP 变化通过。只使用已有受控测试网络，不修改路由器永久配置，不清除配对，不以手动地址覆盖 mDNS 结论。

## 不做什么

不在切换期间传输文件，不测试 PC 睡眠、Windows 重启、大文件、跨互联网、VPN、蜂窝网络、多设备并发或首次配对。不新增网络切换功能、后台服务、重试参数或 UI，除非复现并定位产品缺陷。

## 涉及文件

- `docs/PRODUCT.md`、`docs/TESTING.md` 与本任务验收记录。
- 只有复现真实恢复缺陷时才修改 Windows 发现/连接实现。

## 实现

没有修改产品代码。预检确认 PC 为 `192.168.100.216/24`，Samsung 从已保存的 `Catwrt_5G` 使用 `192.168.100.238/24`，同一路由器还有已保存的 `Catwrt`。ADB 自动开始 Music 共享，Windows 安装版 5.069 秒挂载唯一 P:；切换前 P: 顶层 2 项，规范清单 SHA-256 为 `08B1BDD1639BB98723357062CB97FCA77EDA505DC12DF54458B4AFF24DFAB851`。

在没有文件传输时，从 Android Wi-Fi 设置切换到 `Catwrt`。手机获得新的 `192.168.100.171/24`；Windows 日志先记录一个候选更新，旧会话连续三次健康失败后进入 `Lost`，正常停止原 rclone，再对更新后的候选发起连接并恢复 P:。会话配置回读的实际端点为新地址，旧地址 8273 不可达、新地址 8273 可达。

## 测试

从网络切换开始，P: 在 32.718 秒消失，并在 34.117 秒恢复；按日志时间，新 mDNS 候选约 5.5 秒更新，第三次健康失败发生在约 30.6 秒，原 rclone 成功退出后约 1.9 秒完成新会话挂载。全程只有一个桌面客户端、一个 rclone 和一个 P:。

恢复后 P: 仍为 2 项，规范清单 SHA-256 与基线一致。Windows 两份 `.pairing` 和 `.store.lock` 的 SHA-256 与 P1-026 基线完全相同，证明没有重配对或改写保存身份。

## 验收结果

通过。手机真实 IPv4 从 `.238` 变为 `.171` 后，Windows 通过更新后的发现候选和原保存身份在预设 90 秒内自动恢复，实际 34.117 秒；旧地址没有被继续使用，没有手动地址兜底、重复进程或重复盘符。结束时停止共享，恢复 `Catwrt_5G` 和原 `192.168.100.238`，并确认 8273、P:、Windows 客户端和 rclone 全部不存在。完整记录见 [P1-028 验收](../../audit/P1-028-VALIDATION.md)。
