# P1-022 文件名与路径边界完整性

状态：已完成。验收日期：2026-09-22。

## 目标

在 Samsung 真机共享目录与 Windows P: 上，用最少的代表性样本验证日常会遇到的中文、空格、加号、百分号、emoji、长名称和同名覆盖，确认 Windows 显示、两端内容及安全模式冲突处理正确，覆盖 DATA-04。

## 范围

仅使用 `Music/PhoneBridge-P1-022` 专用目录和小型合成文件。将中文、空格、加号、百分号和 emoji 合并在一个实际文件名中，另用一个接近常用文件系统上限的长名称和一个同名覆盖场景；不做字符排列组合。每个样本只记录 Android 原始名称、P: 可见名称、最终长度和 SHA-256。完成一次手机到 PC 读取、一次 PC 到手机写入/重命名和一次受控同名覆盖即可；只有发现错误时才扩大定位范围。

## 不做什么

不使用用户私人文件，不测试 5,000/10,000 项大目录、视频播放、大文件吞吐、长期运行、三种模式设置、盘符偏好、多设备并发或安装分发。本任务不以放宽路径校验或跳过删除确认换取通过。

## 涉及文件

- `windows/src/PhoneBridge.Mounting/RcloneMountSession.cs`：安全模式改用直写，避免远端拒绝覆盖后保留误导性的脏缓存；完全读写模式保留可恢复缓存。
- `windows/tests/PhoneBridge.Mounting.Tests/MountTests.cs`：锁定三种模式的 rclone 参数边界。
- `docs/audit/P1-022-VALIDATION.md`、`docs/audit/p1-022/`：完成后保存脱敏验收摘要。

优先使用现有 ADB、PowerShell、rclone/WinFsp 和系统散列工具；现有命令足够时不创建新的测试项目。只有复现出产品缺陷时才修改 Android 或 Windows 运行代码。

## 实现

Samsung SM-S9180/API 36 的 `Music` 单个名称上限实测为 255 字节。三个代表性样本完成 P: 读取、PC 上传、重命名和受控覆盖。实测发现安全模式的 rclone `writes` 缓存会在服务端拒绝覆盖后仍暂时显示本地替换内容并留下脏项；修复为安全模式直写、完全读写模式保留可恢复缓存。产品代码只修改该挂载参数分支。

## 测试

组合名称与 244 字节长名称的 P: 读取哈希匹配；PC 新建和重命名后 Android 独立哈希匹配。修复后的同名覆盖保持 Android 和 P: 原内容一致、无脏缓存，新文件直写正常。`PhoneBridge.Mounting.Tests` 44/44、Windows 全量 279/279 通过，Release 构建 0 warnings/0 errors。最终设备与 Windows 资源均已清理。

## 验收结果

通过限定范围。DATA-04 的实际常见名称、长名称、上传、重命名和同名保护取得 Samsung 真机证据。PowerShell 对被拒绝的覆盖仍不报告关闭错误，但最终内容正确且没有脏缓存；模式界面需向用户明确安全模式不替换既有文件。证据见 [P1-022 验收](../../audit/P1-022-VALIDATION.md)。唯一下一任务为 P1-023 三种访问模式与用户设置收口。
