# PhoneBridge NG 使用说明

本说明适用于当前正式版。安装文件请从 [GitHub Releases 的 Latest 正式版本](https://github.com/yang137197/PhoneBridge-NG/releases/latest) 下载，不要使用来源不明的安装包。

## 使用条件

- Windows 11 x64。
- Android 8.0（API 26）或更高版本。
- 手机与电脑连接同一局域网。
- Android 端采用侧载安装；Windows 安装器当前没有商业代码签名。

## 安装

1. 在 Release 的 Assets 中下载 Windows 安装器、Android APK 和 `SHA256SUMS.txt`。
2. 在 Android 手机上允许当前文件来源安装应用，然后安装 APK。
3. 在电脑上运行 `PhoneBridge-NG-Setup-<版本>.exe`。
4. 如果电脑尚未安装 WinFsp，安装程序会启动内置的官方 WinFsp 安装包；确认 Windows 管理员提示后完成安装。

建议安装前使用 PowerShell 核对 SHA-256：

```powershell
Get-FileHash .\PhoneBridge-NG-Setup-*.exe -Algorithm SHA256
Get-FileHash .\*.apk -Algorithm SHA256
```

计算结果应与同一 Release 中的 `SHA256SUMS.txt` 一致。

## 首次配对

全新安装首次打开时，Windows 和 Android 都会显示以下步骤；之后仍可从 Windows“关于 → 使用帮助”和 Android“设置 → 使用帮助”再次查看。已有配对记录的升级用户不会被误判为新用户并强制弹出首次引导。

1. 打开手机上的 PhoneBridge NG，选择要共享的目录并授予所需权限。
2. 点击“配对新电脑”，保持配对页面在前台，记下显示的 8 位配对码。此时无需先开始共享。
3. 打开 Windows PhoneBridge NG，点击“添加手机”，选择发现的手机并输入配对码。
4. 手机上出现电脑名称后，确认是当前电脑并点击“允许配对”。
5. 配对完成后，在手机首页点击“开始共享”。如需锁屏传输，按系统提示允许 PhoneBridge NG 忽略电池优化。
6. Windows 设备卡片显示“已查找到设备，可连接”及当前设备 IP 后，点击“连接”；连接成功后卡片继续显示本次实际使用的设备 IP 和挂载盘符，再点击“打开文件”。

配对码只用于本次配对，请勿发送给他人。无法确认电脑身份时不要允许配对。

## 日常使用

1. 在手机上打开 PhoneBridge NG，确认共享目录后点击“开始共享”。
2. 在 Windows 客户端找到对应设备，点击“连接”。
3. 连接后点击“打开文件”，在文件资源管理器中使用分配给该手机的盘符。资源管理器按“设备备注或设备名 (盘符)”显示，例如 `K40 (E:)`。

一台电脑可以同时连接多台已经配对的手机；每台手机使用独立设备卡片和盘符。Windows 登录时自动运行只会将客户端放入系统托盘，不会自动连接手机或挂载盘符。

资源管理器的容量条显示共享目录所在手机存储的总容量、已用量和应用可用量，而不是只统计已选共享目录中的文件大小。

## 访问模式

每台电脑的访问模式在手机端分别设置：

- 只读：仅浏览和下载，不允许写入或删除。
- 安全模式：允许新建文件，不允许直接覆盖已有文件；删除需要逐项确认。推荐日常使用。
- 完全读写：允许覆盖和删除文件，仅在信任当前电脑且确有需要时使用。

切换访问模式后，应先在 Windows 断开该设备，再重新连接，使新设置生效。

## 设备设置

- 两端的“设备备注”只保存在各自本地，不会同步到另一端。
- 在任一端移除设备只删除该端保存的配对记录；需要重新使用时应重新配对。
- 应用语言可在设置中选择中文或 English，并在重启后保持。

## 正确断开和退出

1. 等待正在复制或写入的文件完成。
2. 在 Windows 对应设备卡片点击“断开”。
3. 如果提示仍有文件等待上传，保持手机共享和网络可用，等待完成后重试。
4. Windows 断开完成后，再在手机上点击“停止共享”。
5. 如需完全退出 Windows 客户端，在系统托盘菜单中选择“退出”。

不要在文件仍在写入时强制结束客户端或停止手机共享。

## 连接失败

按以下顺序检查：

1. 手机仍显示“正在共享”，且手机和电脑处于同一局域网。
2. Windows 客户端点击“刷新”。刷新期间底栏显示“正在刷新设备…”，一次完整发现结束后明确显示找到的设备数量，或“未发现正在共享的设备”；未发现设备不等于程序故障。只有发现服务异常停止时才显示“刷新失败”，此时检查网络后重新打开客户端。
3. 设备至少成功连接过一次后，自动发现失败时设备卡片会明确显示“未发现实时共享，可尝试连接”和“上次连接 IP”；该历史地址只作连接回退，不会显示成当前设备 IP，也不会绕过设备身份验证。若没有实时发现或历史回退地址，卡片显示“未查找到设备，请检查手机打开共享”并禁用连接。若手机地址已经变化，再使用下一项。
4. 已经完成配对但自动发现不可用时，可在“设置 → 高级排障”输入手机当前局域网地址。手动地址不会绕过设备身份验证。
5. 仍无法连接时，在“设置 → 高级排障”导出诊断包。诊断包只保存到用户选择的位置，不会自动上传。

## 升级

Windows 左侧底部显示实际运行版本。点击“检查更新”只会查询 PhoneBridge NG 官方 GitHub Latest Release，不会后台定时检查；当前版本不低于 Latest 时明确提示已是最新版本，不会降级。发现新版本后，用户确认才下载固定名称的 Windows 安装器；文件大小和 GitHub Release 提供的 SHA-256 摘要必须同时通过，之后再次确认才会安全断开全部设备、退出客户端并打开可见安装向导。校验失败、缺少 Windows 安装器或安全卸载失败时不安装。

Android 在“设置”中显示当前版本和“检查更新”。它同样只在点击后查询官方 GitHub Latest Release；发现新版本后，先由用户确认下载，并显示真实下载百分比和进度条，再校验文件大小、SHA-256、应用包名、版本号及与当前应用相同的正式签名。手机仍在共享时不会安装；请先停止共享并确认 Windows 已断开。首次使用时 Android 可能要求允许 PhoneBridge NG 作为安装来源，随后仍会显示系统安装确认，应用不会静默安装。

Windows 和 Android 正式版都应直接原位升级，不需要先卸载。升级前先结束文件传输；升级后核对版本、原有配对、设置和基础连接是否保留。每个新正式候选仍须使用同签名制品完成真实检查、下载、系统安装和状态保持验收；正式升级来源以 GitHub Releases 中紧邻的前一个正式版本为准。

如果 Windows 客户端检测到旧版网络盘显示缓存，会在连接手机前询问是否重启 Windows 资源管理器。该操作会关闭全部文件资源管理器窗口；请先完成正在进行的复制或移动，再点击“确定”。点击“取消”不会清理或重启，并会在下次启动时再次提示。
