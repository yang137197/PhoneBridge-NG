# P2-014 — v0.2.3 有界自动重连

状态：实现与自动验证完成。日期：2026-09-28。

## 目标

把仅适用于活动连接临时断网的自动恢复改为有界状态机：手机明确停止共享时不重连；无法区分原因的网络中断最多执行 6 次实际重连或持续 2 分钟；耗尽后停止自动恢复并要求用户手动连接。

## 范围

- 保留挂载期间每 5 秒健康检查、普通故障三次确认、mDNS 消失后的两次加速确认，以及同一 `device_id`、CA、凭据和模式复验。
- 保留 `2/5/10/20/30` 秒退避，实际重连尝试最多 6 次，恢复窗口最多 2 分钟，任一先到即停止。
- 重连成功后连续三个 5 秒健康周期才清空本轮恢复预算；短暂恢复后再次掉线仍属于同一恢复轮次。
- 活动会话明确返回 `share_ready=false` 时立即停止自动恢复；身份、授权、记录、模式和挂载终止错误继续立即失败关闭。
- 候选消失时显示等待状态，不保留已失效的“若干秒后重试”；耗尽后显示必须手动连接，并释放无待写数据的盘符预留。
- 保持现有安全停止和脏缓存保护；达到重连上限不能删除、强制结束或冒充已提交待上传数据。
- Windows 开发版本更新为 `0.2.3`，正式交付物、标签和 Release 另立候选任务。

## 不做什么

- 不新增 Android 停止通知协议，不把不可靠的 mDNS 消失单独认定为用户主动停止。
- 不改变 HTTPS/WebDAV、rclone、WinFsp、配对、安全存储或盘符分配路线。
- 不发布 GitHub Release，不覆盖当前安装的 `v0.2.2`，不把自动测试写成真机验收。
- 不重复大文件、双设备、睡眠、重启或全新机器完整矩阵。

## 实现

`ReconnectPolicy` 为每台设备保存恢复开始时间、截止时间、实际尝试次数和稳定健康周期。安全卸载后才开始 2 分钟窗口；有同身份端点且退避到期时才计一次实际尝试。连接成功只进入待稳定状态，连续三个健康检查通过后才清零；短暂恢复后再次掉线继续原轮次。

桌面监督器在候选缺失时显示有限等待，在 `share-not-ready`、第 6 次失败或 2 分钟到期时清除恢复意图并调用同一安全停止路径。成功停止会释放盘符预留并显示必须手动连接；安全停止失败继续显示原错误并保留受保护资源。中英文文案显示当前尝试次数和上限，不再保留失效倒计时。

协调器区分“本次连接新取得的盘符预留”和“恢复轮次已经持有的预留”：普通首次连接失败只释放本次新预留，恢复尝试失败继续保留原盘符，直到恢复成功、用户主动断开或预算耗尽。

Windows 和 Android 版本元数据更新为 `0.2.3`；正式交付目录、GitHub Release 和对应源码脚本仍保持 v0.2.2，等待独立候选任务绑定实际制品。
