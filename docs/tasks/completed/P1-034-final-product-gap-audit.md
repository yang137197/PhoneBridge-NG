# P1-034 — 最终产品必要缺口审计

状态：已完成。日期：2026-09-23。

## 目标

以当前源码、最终需求、MVP 验收和本地交付包为依据，逐项确认第三方本地使用前是否仍存在必须开发或修复的产品缺口，并排除已完成、非目标或仅属公开发行增强的事项。

## 范围

只读核对 `AGENTS.md`、产品/安全/测试规范、当前源码、现有验收记录、安装器/APK manifest、许可和交付清单；每个结论必须指向直接证据并标记为已满足、真实缺口、非当前范围或证据不足。

## 不做什么

不修改产品运行代码，不重复真机、大文件、睡眠或重启测试，不新增功能，不发布 Release，不把公开商店、商业签名、同时多设备或自动更新提升为当前必做项。

## 涉及文件

- 当前需求、架构、安全、测试和交付文档。
- Windows/Android 入口、资源、manifest、安装与构建配置。
- 现有 P0/P1 验收记录及交付 manifest。
- 本任务、验收记录和机器可读缺口矩阵。

## 实现

逐项核对 MVP-01–15、配对/TLS/安全存储、三种模式、双向文件操作、1/5/10/20 GB、视频 Seek、中断恢复、锁屏、Android 重启、PC 睡眠、IP 变化、大目录、日志、托盘、自启动和当前交付包。结论按“已满足、稳定分发前必需、材料证据缺口、非阻塞范围差异、当前非目标”分类，避免把所有未测排列组合变成继续开发理由。

确认没有新的运行缺陷。当前主链路和本机本地交付已满足；稳定第三方分发前的首要真实缺口是构建脚本仍将 Android APK硬编码为 `androiddebugkey` 和公开 Debug 密码，产物也明确标为 `local-test`。第二项是全新、没有 WinFsp 的 Windows 安装分支只有代码、固定 MSI 散列/签名和编译证据，没有真实干净系统运行证据。

Windows 未作 Authenticode 签名只会产生本地安装警告，不作为当前功能阻塞。首次手动 IP 配对、详细托盘快捷菜单、物理磁盘满/断电和同时多设备挂载分别保留为范围差异或证据边界；没有现实故障证据时不扩展实现。应用商店、自动更新和公开发布不在用户授权范围。

## 验收结果

已完成并通过审计。当前产品对已验证的 Windows 11 x64、Samsung/Redmi 和本地安装场景已具备完整 MVP 主链路，没有发现需要立即修复的运行缺陷；但当前制品仍是本地预览，不能因功能通过就称为稳定可转交的第三方发行包。

唯一下一任务是把 Android 构建从硬编码 Debug 签名改为显式、失败关闭的长期第三方发行签名路径，并定义私钥、密码、备份和产物标识边界。该任务先完成代码、验证器和不含秘密的构建接口；只有在生成实际长期密钥前才需要用户确认具体保存与备份位置。
