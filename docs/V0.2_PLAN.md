# PhoneBridge NG v0.2.0 需求与开发计划

状态：P2-008 已完成，`v0.2.0` 已通过正式验收、发布 GitHub Release 并成为后续升级的首个基线。r21 UI/语言与 r20 多设备证据继续有效。日期：2026-09-26。

## 1. 用户、核心场景、非目标和正式交付物

### 用户

使用 Windows 11 和一台或多台 Android 手机，希望在同一局域网内通过文件资源管理器访问手机文件、不使用云账号，并希望界面简单易懂的用户。

### 核心场景

1. 首次使用：手机先打开“配对新电脑”，Windows 发现手机并用一次性配对码完成配对；手机随后开始共享，用户在 Windows 手动点击“连接”。
2. 日常使用：用户打开 Windows 客户端，在设备卡片上点击“连接”；连接后点击“打开文件”。
3. 手机管理：用户在手机端选择既有目录或“手机存储”、开始或停止共享、批准新电脑，并在停止共享后仍可管理已配对电脑。
4. 多设备：一台 Windows 电脑同时连接至少两台 Android 手机，每台手机使用独立盘符，连接、传输和断开互不影响。
5. 设置与排障：语言、自启动和必要偏好放在设置中；手动地址和诊断导出放在高级或排障入口；设备设置只保留明确的本地移除。

### 本版本非目标

- 不更换 HTTPS/WebDAV、rclone、WinFsp、mDNS、配对协议或安全存储路线。
- 不增加云账号、远程访问、同步、投屏、剪贴板、自动登录挂载或自研文件系统驱动。
- 不加入多套主题选择器；本版先交付一套统一的现代浅色主题。后续只有在用户明确需要时再增加深色主题。
- 不因 UI 重构重复 5/10/20 GB、PC 睡眠或其他已经通过且没有相关缺陷的测试。
- 不把“一台手机同时服务多台 Windows 电脑”作为本轮新增目标；本轮多设备特指一台 Windows 电脑同时连接多台手机。
- Android APK 永久只通过 GitHub 分发，不增加 Google Play 或其他应用商店上架工作。

### 正式交付物

- 更新后的 Windows 安装器和仅通过 GitHub Release 分发的 Android APK。
- Windows 与 Android 共用视觉语言的新 UI，以及各平台合适的新版应用图标、托盘图标和安装图标。
- 默认简体中文、可在设置中切换 English，所有可见文本完整本地化并持久保存选择。
- Windows 同时连接至少两台手机的能力，以及每台设备独立的盘符、状态、缓存、重连和安全卸载。
- 与二进制对应的源码包、许可材料、散列、manifest、升级说明和验收记录。

## 2. 已确认的当前事实

- v0.1.0 Windows 主界面同时展示配对码、端点、盘符、删除路径、手动地址和九个操作按钮；P2-003 已按 r1 分为设备、设置、关于及子页面，接入 A 应用图标，并由用户复验通过。
- P2-006 已让 Windows 语言选择立即刷新窗口、卡片、状态和托盘并按数据根持久化；Android 页面和后台通知共用同一应用语言。r21 Windows 与 Redmi 的当前界面和冷启动 English 保持已实测。
- Windows 已由 P2-005 改为按 `device_id` 隔离的设备会话；每个会话独立持有 `ConnectionClient`、`ReadOnlyMountManager`、盘符、rclone/RC、取消、健康检查和重连状态，协调器只管理集合、冲突与退出。
- 已有发现、配对、凭据、单设备挂载、断线恢复、托盘、日志、签名和发布链路可继续复用；没有证据要求更换既定技术路线。
- Android 当前使用原生 Kotlin 和程序化纵向布局，功能可用，但缺少明确的信息层级、卡片状态和统一视觉规范。

## 3. 推荐的界面方案

### 3.1 统一视觉方向

- 参考用户截图的浅灰背景、白色卡片、蓝色主色、圆角、留白和简洁线性图标；不复制参考产品的品牌、图标或具体布局资产。
- 主色建议使用清晰的科技蓝，辅以青色状态色；成功、警告和错误仍使用独立语义色，不能只靠颜色表达状态。
- 两端统一设备、连接、共享、文件和安全图形语言，同时遵守各平台原生交互习惯。
- 本版只实现浅色主题，但颜色、间距、字号和圆角集中为设计变量，为后续深色主题保留条件。

### 3.2 Windows 信息架构

左侧只保留三个入口：

1. **设备**：默认页，展示附近和已配对手机。
2. **设置**：语言、Windows 自启动、默认盘符分配方式和高级排障。
3. **关于**：版本、许可证和项目链接。

设备页使用卡片，不再使用空白大表格和一整排按钮。每张卡片只展示设备名称、连接状态、访问模式、盘符和一个随状态变化的主操作：

| 状态 | 主操作 | 次要操作 |
| --- | --- | --- |
| 未配对 | 配对 | 查看设备信息 |
| 已配对、未连接 | 连接 | 设备设置 |
| 正在处理 | 进度状态 | 取消（只在操作进行时出现） |
| 已连接 | 打开文件 | 断开、设备设置 |
| 需要处理 | 继续连接 | 查看原因 |

“添加手机”打开独立配对流程：手机打开“配对新电脑” → Windows 选择手机 → 输入 8 位配对码 → 等待手机批准。配对成功只保存身份，不自动连接或挂载；手机开始共享后，用户回到设备卡片手动点击“连接”。配对码、端点和盘符不常驻主界面。

配对成功后 Windows 自动返回设备首页。设备设置只保留一个“设备备注”，备注作为该手机在本机的显示名称并在重启后保持，但不改变 `device_id`、凭据、手机端名称或协议身份。Android 的每台已配对电脑也有独立的本机设备备注；两端备注不互相同步。

### 3.3 现有 Windows 操作的精简

| 当前操作 | 建议结果 |
| --- | --- |
| 配对并连接 | 拆为“添加手机”中的“配对”和设备卡片的“连接”；配对成功不自动挂载 |
| 连接 / 恢复确认 | 普通状态显示“连接”；只有确有未完成配对时显示“继续连接” |
| 取消 | 仅在配对、连接或安全卸载正在执行时出现 |
| 打开盘符 | 改名“打开文件”，仅在该设备已连接时作为主操作 |
| 卸载 | 改名“断开”，放在对应设备卡片的次要操作中 |
| 撤销配对 / 仅忘记本机 | 合并为“移除此手机”：停止本机连接并删除 Windows 配对信息，不请求手机确认；再次连接按新设备配对 |
| 确认删除和路径输入 | 从主界面移到“设备设置 → 安全操作”，改名“授权一次删除”，说明只用于安全模式下已被阻止的删除 |
| 手动 IP/端口 | 放入“设置 → 高级排障”，仍保持身份校验 |
| 导出诊断包 | 放入“设置 → 高级排障” |
| Windows 自启动 | 放入“设置 → 常规”；仍只启动客户端，不自动连接或挂载 |

### 3.4 Android 信息架构

主页只保留：

- 顶部品牌与共享状态；
- 当前共享目录卡片；
- 一个醒目的“开始共享/停止共享”主按钮；
- 始终可用的“配对新电脑”入口；配对不要求先开始共享；
- 已配对电脑卡片及其访问模式摘要。

权限未满足时才显示权限卡片；获得权限后不继续占据主操作区。共享目录保留 Music、DCIM、Pictures、Download、Movies、Documents、Android/media，并在末尾增加“手机存储”，指向系统允许访问的内部共享存储根目录。停止共享后仍从加密配对库展示全部已配对电脑。访问模式与“移除此电脑”进入对应电脑详情；移除会删除手机本地配对信息并断开旧连接，不请求远端确认。右上角设置进入独立菜单，语言位于其子页。配对码和批准操作只在配对会话存在时显示。

子页返回手势或虚拟返回键返回上级页面；首页第一次返回提示再次返回，第二次在共享中只把界面置于后台、未共享时退出。设置中的“退出应用”明确停止共享后退出。

两端均允许系统截屏，不设置应用级安全阻挡。截屏可能包含设备名称、目录或配对界面，内容保存和分享由用户决定。

### 3.5 图标方向

新版图标使用原创的“手机 + Windows 文件/盘符 + 连接桥”抽象符号，减少文字和细碎线条。主图标使用蓝色到青色的有限色板，保证在 16 px 托盘尺寸仍能辨认。

正式资产至少包括：

- 可编辑矢量源文件；
- Windows 多尺寸 `.ico`、应用图标、安装器图标和单色托盘变体；
- Android adaptive icon 的 foreground/background、圆形适配和 Android 13 monochrome 资源；
- GitHub 分发所需的高分辨率 PNG；永久不增加 Google Play 或其他应用商店发布工作。

### 3.6 语言行为

- 两端首次启动均固定使用简体中文，不再由系统语言替用户决定。
- 设置中提供“简体中文”和“English”两项；切换后当前界面受控刷新并持久保存，重启后保持。
- Windows 主窗口、托盘、对话框、错误信息和诊断入口使用同一选择；Android 页面、通知、权限说明和对话框使用同一选择。
- 协议错误码和日志字段保持稳定，不因显示语言变化。

## 4. 多设备技术建议

### 可复用

- 设备发现、配对协议、凭据记录、严格 TLS、单个 rclone/WinFsp 挂载会话、VFS 缓存检查和安全卸载规则。
- Android 每台手机现有的共享服务；一台 Windows 连接多台手机不要求更换手机端协议。

### 必须重构

- 将全局唯一的 `ConnectionClient`/`MountManager` 所有权改为按 `device_id` 隔离的设备会话。
- 每个会话独立持有盘符、rclone 进程、RC 端口、缓存目录、取消令牌、健康检查、重连状态和日志上下文。
- 增加一个轻量会话协调器，只负责设备会话集合、盘符冲突、应用退出和托盘汇总；不能让一个设备的取消或失败影响其他设备。
- 盘符默认自动选择空闲项，并允许在设备设置中指定偏好；冲突必须在连接前明确提示。

### 第一条多设备通过线

Samsung 与 Redmi 在同一真实局域网内同时连接为两个不同盘符；两个盘符都能打开、读取和各完成一次双向文件复制。停止其中一台手机或断开其中一个盘符时，另一台仍可浏览和传输；进程、缓存、凭据和日志不能串设备。该通过线不重复与本改动无关的大文件、睡眠和重启矩阵。

## 6. 预期效果

- 用户打开 Windows 客户端后，不再面对九个并列按钮和多个技术输入框；日常只需识别设备并使用“连接/打开文件/断开”。
- 高风险和排障操作仍然可用，但不会干扰普通流程，也不会削弱现有安全确认。
- 手机端首页能一眼看出是否正在共享、共享哪个目录以及哪些电脑已获授权。
- 两端首次显示简体中文，用户需要时可明确切换英文。
- 同一台 Windows 电脑可以同时使用至少两台手机，每台设备的状态和失败相互隔离。
- 视觉风格统一、图标在桌面、安装器、任务栏、托盘和手机桌面上都能清楚辨认。
